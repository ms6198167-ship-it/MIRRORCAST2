# MirrorCast — build, setup, tests, and status

## What is included

- `MirrorCast/`: native SwiftUI iOS app source, AirPlay route picker, Bonjour discovery, and Windows receiver IP/port settings.
- `MirrorCast/BroadcastExtension/SampleHandler.swift`: ReplayKit Broadcast Upload Extension source. It rate-limits video to about 12 frames/s, encodes screen frames as JPEG, and forwards app/microphone audio sample-buffer bytes to the receiver over the v1 framed TCP protocol.
- `WindowsReceiver/`: runnable Python receiver with a basic desktop UI, Bonjour advertisement, packet validation, video-frame display, audio packet capture, and protocol tests.

## Important platform requirement

The Windows receiver runs on Windows. Building/signing the native iOS app and its ReplayKit Broadcast Upload Extension requires macOS and Xcode; Windows-only users can run the receiver and tests but cannot produce an iOS installable build from this source alone. This repository is source code, not a signed IPA or App Store-ready app.

## Windows receiver build/run

```powershell
cd WindowsReceiver
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m unittest discover -s tests -v
python receiver.py
```

No native compilation is needed for the Python receiver. It uses the standard library plus Pillow for image display and zeroconf for Bonjour discovery.

## iOS project setup (requires Mac + Xcode)

1. In Xcode, create an iOS App project named `MirrorCast` using SwiftUI, Swift, iOS 16+.
2. Add all Swift files under `MirrorCast/` to the app target except `BroadcastExtension/SampleHandler.swift`.
3. Add a **Broadcast Upload Extension** target named `MirrorCastBroadcast`, and add `SampleHandler.swift` to that extension target only. Verify ReplayKit extension template settings against the installed Xcode version.
4. Add the same App Group entitlement to both targets: `group.com.example.MirrorCast`. Replace this placeholder with an App Group identifier registered to your Apple Developer team before device testing.
5. Add `NSLocalNetworkUsageDescription` with value `MirrorCast sends your screen and selected audio to a receiver on your local network.` and `NSBonjourServices` containing `_mirrorcast._tcp` to the app's Info.plist. Add required privacy descriptions and extension metadata as generated by Xcode's Broadcast Upload Extension template.
6. For local development, allow local network access when prompted. On the iPhone and Windows PC, use the same trusted Wi-Fi/LAN.
7. Enter the PC's local IPv4 address and port 8765 in the app. Open iOS Control Center, long-press Screen Recording, select MirrorCast's broadcast extension, and start the broadcast.
8. For a device build, configure valid bundle IDs, signing teams, provisioning profiles, and App Group capability for both targets.

The extension's use of `group.com.example.MirrorCast` is intentionally a placeholder and must match the App Group configured in Xcode. ReplayKit may require an actual device and explicit broadcast consent; Simulator testing is not sufficient.

## Protocol v1

TCP framing is `MCST` (4 bytes) + unsigned 32-bit big-endian JSON-header length + UTF-8 JSON header + exactly `length` payload bytes. Header keys include `v: 1`, `kind`, and `length`. Supported kinds: `hello`, `video`, `audio_app`, `audio_mic`, `end`. `video` currently uses JPEG frames. Audio metadata includes sample rate, channels, and presentation timestamp when ReplayKit exposes them.

## Tests

The automated tests exercise frame encoding/decoding, zero-length control packets, oversized-payload rejection, and bad-magic rejection. Run the command above. These are protocol unit tests, not a full iPhone-to-PC integration test.

## Honest status (2026-10-15)

| Capability | Status |
|---|---|
| Python Windows receiver | Implemented; not packaged as an installer |
| Bonjour receiver advertisement | Implemented when `zeroconf` is installed; depends on network/firewall configuration |
| JPEG screen-frame transport and display | Implemented in source; requires device integration test |
| ReplayKit screen capture | Source included; not compiled/device-tested here |
| App-audio and microphone payload transport | Source included; not compiled/device-tested here |
| Audio decode/playback and A/V synchronization | Not implemented |
| TLS, verified pairing, replay protection | Not implemented; current prototype is trusted-LAN only |
| Native remote control of iPhone | Not implemented; iOS does not provide general-purpose third-party remote touch injection |
| AirPlay | Uses Apple's system route picker; does not make MirrorCast an AirPlay receiver |
| Mac/TV receivers | Not implemented; protocol is intended to be extended after validating the Windows receiver |
| iOS build / integration test | Not run: Xcode/macOS unavailable in this environment |

## Known risks and next milestones

1. Build the app and extension in Xcode; resolve SDK/toolchain warnings and test ReplayKit callbacks on a physical iPhone.
2. Add TLS with receiver identity verification and short-lived explicit pairing before use beyond a trusted lab LAN.
3. Normalize audio to a documented PCM format, implement decoding/playback and timestamp-based A/V sync.
4. Add bounded queues, congestion handling, reconnection, adaptive frame rate/quality, and integration tests.
5. Implement separate receivers per platform and publish a compatibility matrix only after actual testing.
